# 装备查询面板

2026-11-04。新标签页 **装备查询 / Gear query**。做的是"决定要什么"，还没做"去市集找"。

## 左半边：当前装备

- 顶部选部位（武器、头盔、靴子…），读的是你已导入的装备（`store.equipped`）。
- 每条词缀：原文、它命中的档位 `T{n}`、所属组；
- 下面是一条**档位滑条**：`至少保留 T{n}`，左边 T1（最强）、右边该组最弱的一档；
- 右侧三选一：`数值不降`（same roll or better）/ `只看阶级`（tier only）/ `不要求`（not required）。
- 选择会记进设置（`settings.gearQuery`，键是 `部位|原文`），换部位再回来还在。

**Tier 怎么来的**：PoB 自带词缀池（Item / Runes / Exclusive / Desecrated）里，同一个 `group` 按物品等级降序编号，T1 最强。匹配时把数字统一成 `#` 比形状，再用实际数值落进哪一档决定 Tier（`src/core/affix-match.js`）。

属性行（`Item Level:`、`Energy Shield:`、`Grants Skill:` 等）会被过滤掉——它们不是词缀，列出来只会得到一排"无法判定阶级"。

## 右半边：换装后必须满足

三层，来自 `src/core/guard-conditions.js`：

- **角色**：随角色保存（`settings.guards[角色]`）。
- **这个部位**：随角色 + 部位保存；武器相关条件再带武器组。
- **仅本次查询**：只在这次面板会话里，不进存储。

每层都能加"某个指标 不下降 / ≥ 数值 / ≤ 数值"，也能删。临时层如果比已保存的条件更松，会在合并时进 `conflicts`，**不会静默生效**。

## 候选与验证（2026-11-04 追加）

面板底部多了「候選裝備」：

1. **搜尋候選**：把每条"要求保留"的词缀变成交易站筛选（`数值不降` 取当前数值，`只看阶级` 取该档下限），按当前部位的类型过滤，价格升序取前 10 条。词缀原文会被转成交易站的 `#` 形状再匹配（`tradeShape`）。
2. **逐件用 Path of Building 驗證**：每件候选放进构筑算一遍，拿 `before/after` 跑三层条件，得到 `通过 / 失败 / 未验证`；失败的会列出是哪项条件、差多少。

**没有条件时是"未验证"，不是通过**——`overall([])` 现在返回 `unverified`，面板也会说明原因。

### 实测（真实交易站，Forbidden Rites）

```
武器（長矛）：6 条要求词缀 → 2264 件候选，取前 10
加一条全局条件「DPS 不下降」→ 验证 10 件：全部 失败，DPS -300k ~ -308k
```

这正是"搜到 ≠ 通过"：筛选只保证词缀在，换上便宜的长矛伤害会掉 30 万，条件把它拦住了。

## 还没有的

- 词缀"替换"（这条不要了、换成冰抗）还没有对应控件。
- 价格/预算没有单独的上限控件（现在用设置里的预算）。
- 验证是串行的，10 件大约十几秒；更多候选要分批。
- 候选只取前 10 条，没有分页。
